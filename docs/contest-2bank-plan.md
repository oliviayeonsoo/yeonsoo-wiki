# 공모전 제안서 구상 — 외국인 직원 급여명세서 자동화

요강은 `contest-2bank.md` 참고. 이 문서는 아이디어 방향과 제안서 논리 흐름 메모.

> 표시 ⚠ = 수치·사실을 제출 전에 원출처로 반드시 확인할 것

---

## 0. 아이디어 한 줄

> 외국인 직원을 둔 사장님이 케이뱅크·카카오뱅크 앱에서 **급여를 이체하면 그 데이터로 다국어 임금명세서가 자동 생성·발송**되고, 직원은 **명세서와 실제 입금액을 직접 대조**할 수 있는 기능.

- 공모 주제: **3번(소상공인 금융 페인포인트)** 메인, **1번(개인사업자 대출)** 연결
- 원래 아이디어(외국인 근로자 관점)를 **사장님 관점으로 뒤집은 것**. 핵심인 "명세서 vs 실입금 대조"는 그대로 유지

### 관점 전환

| 외국인 근로자가 겪는 것 | 사장님이 겪는 것 |
|---|---|
| 급여명세서를 못 받음 | 명세서 발급이 번거로워서 안 해줌 |
| 공제 내역이 뭔지 모름 | 외국인 직원과 급여 분쟁 리스크 |
| 앱을 송금날만 씀 | 급여 이체 말고는 사업자 뱅킹 앱을 안 씀 |

### 효과 3가지

- **사장님:** 명세서 발급 의무를 쉽게 지키고, 급여 분쟁을 미리 막음
- **은행:** 사장님은 급여 처리 때마다, 직원은 매달 확인하러 들어와서 앱 이용(DAU)이 늘어남
- **공모 주제와의 연결:** 소상공인 페인포인트 해결 + 사업자 계좌 활성화

## 1. 전체 논리 흐름 (한 문장씩)

1. **모든 사장님**은 2021년 11월부터 임금명세서를 줘야 한다. 하지만 영세 사업장은 제대로 못 지킨다. (보편적인 문제)
2. 그중 **외국인 직원을 둔 사장님**은 이 문제가 몇 배로 커진다. 언어, 숙식비 공제, 분쟁, 고용허가 제한 때문이다. (가장 아픈 세그먼트)
3. 인터뷰해 보니 명세서를 안 주는 건 의도가 아니라 **"번거로워서/어떻게 하는지 몰라서"**였고, 진짜 걱정은 **분쟁**이었다. (근거)
4. 기존 해결책은 **사장님이 따로 입력해야 하거나**(급여 SaaS·엑셀), **근로자가 이해하지 못한다**(한국어, 단방향 발송). (빈자리)
5. 급여 이체는 이미 **은행 앱에서 일어난다**. 그러니 명세서를 만드는 데 가장 적합한 곳은 은행이다. 그리고 비대면 은행인 케뱅·카뱅이 가장 잘할 수 있다. (왜 우리, 왜 호스트인가)
6. 솔루션: 이체 → 자동 명세서 → 다국어 발송 → 근로자 대조 → 발급 기록 보관. (무엇을)
7. 은행은 **사업자 주거래 고객 + 외국인 신규 고객 + 대출 심사 데이터**를 얻는다. (왜 은행이 해야 하나)
8. 실행 로드맵과 리스크 대응. (실현 가능성)

**문제 인식 구조의 핵심:** 처음부터 "외국인 근로자" 이야기로 시작하면 심사위원이 *니치하다*고 느낄 수 있다.
**보편적인 의무(모든 사장님) → 가장 아픈 세그먼트(외국인 고용 사업장)**로 좁혀 가야 시장성과 날카로움을 둘 다 잡을 수 있다.
외국인 사업장은 첫 공략 시장(비치헤드)이고, 확장 대상은 모든 사업자 급여이체라고 말하는 구조.

## 2. 문제 인식 — 근거로 쓸 재료

### 2-1. 법적 의무 (보편적인 문제)
- 근로기준법 제48조 제2항: **임금명세서 교부 의무**. 2021.11.19 시행. **5인 미만 사업장 포함 전 사업장**에 적용. 위반하면 과태료 최대 500만 원 ⚠
- 필수 기재사항: 성명·생년월일(사원번호), 지급일, 임금 총액, 항목별 금액, **계산 방법**, **공제 내역** ⚠
- 전자 교부(문자·메신저·이메일)도 인정된다 → 앱 발송이 합법적인 교부 수단 ⚠
- 고용노동부가 무료 작성 도구(엑셀/웹)를 주지만 **직접 입력해야 한다** → "번거롭다"의 근거

### 2-2. 외국인 고용 사업장이 더 아픈 이유
- **규모:** 외국인 취업자 약 100만 명 수준(통계청 이민자체류실태). E-9 도입 쿼터는 2024년 16.5만 명으로 역대 최대 ⚠
- **업종 확대:** 2024년부터 E-9 허용 업종이 음식점업(일부 지역)·임업·광업으로 넓어졌다. 즉 **소상공인**이 외국인을 고용하는 경우가 늘고 있다 ⚠
- **공제 항목이 복잡하다.** 숙식비 공제(고용노동부 지침상 서면 동의 + 통상임금의 일정 비율 한도), 4대보험, 출국만기보험 등 내국인보다 계산이 까다롭다 → **분쟁의 단골 원인** ⚠
- **분쟁 비용이 크다.** 외국인 근로자 임금체불은 연 1,000억 원대 ⚠. 체불로 판정되면 **외국인 고용 제한** 같은 불이익이 있을 수 있다 ⚠ → 사장님에게는 "직원 한 명 분쟁 = 앞으로 고용 못 할 수도"
- **언어:** 한국어 명세서는 받아도 이해를 못 한다 → 오해 → 분쟁

### 2-3. 인터뷰로 검증할 가설 (10명 이상 필수)
| # | 가설 | 물어볼 것 |
|---|---|---|
| H1 | 명세서를 안 주는 이유는 고의가 아니라 번거로움·무지 때문이다 | 지금 명세서를 어떻게 주나? 안 준다면 왜? 누가 급여 계산을 하나(본인/세무사)? |
| H2 | 외국인 직원과 급여 관련 오해·분쟁 경험이 있다 | 공제(숙식비 등) 설명할 때 어려웠던 점? 항의받은 적 있나? |
| H3 | 급여는 이미 은행 앱으로 이체한다 | 어느 은행, 어떤 방식(일괄/개별)? 이체 말고 앱을 쓰나? |
| H4 | 자동으로 만들어 주면 쓰겠다 / 돈을 낼 의향 | 이 기능이 있으면 주거래 은행을 옮기겠나? |

- **인터뷰 대상 주의:** E-9 비자는 **편의점·세탁소 취업이 원칙적으로 안 된다** ⚠. 편의점·식당에는 H-2(방문취업 동포)·F계열 비자가 많다. 이렇게 섞는 걸 추천:
  - 소규모 제조업(뿌리산업)·농축산 사장님 → E-9 중심, 공제 이슈가 가장 크다
  - 식당 사장님 → H-2 / E-9(음식점 시범)
  - 가능하면 **외국인 근로자 3~5명 추가** → 양쪽 모두에서 검증 (요강상 인원 제한 없음)
- 참여 확인서 필수. 사진·녹음은 동의를 받은 경우만.

## 3. 경쟁 분석

### 3-1. 경쟁 그룹 4개
| 그룹 | 예시 | 강점 | 빈틈 |
|---|---|---|---|
| ① 급여·HR SaaS | 시프티, 플렉스, 알바 플랫폼의 급여/근로계약 기능, 캐시노트 등 ⚠ | 근태·급여 계산 | 이체와 따로 놀아서 **이중 입력**. 유료·중견 기업 위주. 다국어·근로자 대조 없음 |
| ② 세무·노무 대행 | 기장 세무사, 삼쩜삼·자비스류 | 계산 정확 | 명세서를 근로자에게 **전달·설명하는 단계가 없다**. 월 비용 |
| ③ 시중은행 | 기업뱅킹 급여이체(신한·KB 등), 외국인 특화(하나·우리 등 외국인 전용 앱·일요 영업점) ⚠ | 이체 인프라, 외국인 고객 기반 | 사업자용과 외국인용이 **분리**돼 있다. 이체 데이터를 명세서로 잇지 못한다 |
| ④ 송금 핀테크·공공 도구 | 한패스·센트비·GME 등, 고용노동부 명세서 도구, EPS | 외국인 친화 / 무료 | 송금은 근로자 쪽만 다룬다. 공공 도구는 수기 입력 |

### 3-2. 포지셔닝 맵 (장표 1장)
- X축: **사장님 추가 작업**(별도 입력 필요 ↔ 이체만 하면 끝)
- Y축: **근로자 이해·확인**(단방향·한국어 ↔ 다국어·입금 대조 양방향)
- 기존 업체는 모두 왼쪽 아래나 한쪽 끝에 몰려 있다. **오른쪽 위가 비어 있다** → 우리 자리

### 3-3. 차별점 (3가지로 압축)
1. **Zero 입력:** 명세서의 원천이 *이체 거래 자체*다. 사장님은 공제 항목을 템플릿으로 한 번만 등록하면 된다.
2. **양방향 대조:** 근로자가 명세서와 실입금을 직접 맞춰 본다. 분쟁의 원인인 *불신*을 줄이는 장치다.
3. **증빙 기록:** 발송·열람 기록이 남아 사장님에게 **교부 의무를 이행했다는 증거**가 된다. 분쟁 때 방패.

### 3-4. 왜 케이뱅크·카카오뱅크인가
- 비대면 + 모바일 중심이라 소상공인 급여이체에 맞는 구조
- **카카오톡**: 근로자가 앱을 깔지 않아도 알림톡/링크로 명세서를 받을 수 있다 → 근로자 쪽 도입 장벽이 낮다
- 두 은행 모두 **개인사업자 대출**을 키우는 중 → 급여 지급 이력이 **대안 신용평가 데이터**가 된다 (주제 1과 연결)
- ⚠ 두 은행의 현재 사업자 통장·외국인 계좌개설 지원 범위를 확인하고, **이미 상용화된 기능이 아님**을 반드시 확인할 것 (상용화된 과제는 실격 사유)

## 4. 솔루션 구성

1. **설정(최초 1회):** 직원 등록(국적·언어·비자), 공제 템플릿(4대보험·숙식비·기타). 숙식비 등은 서면 동의 체크 기능 포함
2. **급여 이체:** 기존 이체 화면에서 "명세서 함께 보내기" 토글
3. **자동 생성:** 이체 금액 + 템플릿으로 법정 기재사항을 채운 명세서를 만든다. **한국어 + 근로자 모국어** 병기
4. **발송:** 카카오톡 알림톡 / 문자 링크. 받는 쪽 은행은 상관없음
5. **근로자 대조:** "명세서상 실지급액 = 입금액" ✓ 표시, 항목별 설명(예: 숙식비 공제가 뭔지)을 쉬운 말로
6. **기록·이의제기:** 열람 확인, 질문하기 → 사장님에게 전달 (분쟁 전에 대화)

장표는 사장님 화면 2~3개 + 근로자 화면 2개면 충분하다(목업).

## 5. 은행 입장의 효과 (비즈니스 모델)

| 지표 | 내용 |
|---|---|
| 사업자 주거래화 | 급여이체 계좌 = 주거래 계좌. 매달 들어오는 이유가 생긴다 |
| DAU/MAU | 사장님(급여일) + 근로자(매달 확인) 양쪽에서 |
| 신규 고객 | 외국인 근로자 → 계좌·해외송금·소액대출 고객으로 |
| 대출 연계 (주제 1) | 정기 급여 지급 이력 = 사업 안정성 신호 → 개인사업자 대출 심사 보조 데이터, 명세서 화면 안에서 대출 상품 노출 |

- 수익 모델은 무료 기능으로(획득 도구) → 대출·송금·예금으로 회수. 이걸 분명히 해야 "왜 은행이 공짜로 해 주나"라는 질문을 막을 수 있다.

## 6. 예상 반론과 대응

| 반론 | 대응 |
|---|---|
| 외국인 고용 사업장만 대상이면 시장이 작다 | 비치헤드일 뿐 기능은 모든 사업자 급여이체에 쓸 수 있다. 외국인 사업장은 페인이 가장 커서 첫 도입 동기가 강하다 |
| 사장님이 투명성을 원치 않을 수 있다 | 내세우는 가치는 "착한 일"이 아니라 **과태료·분쟁·고용 제한 리스크 감소**다(인터뷰 근거로) |
| 공제 계산 오류의 책임은? | 은행은 계산 엔진이 아니라 **사장님 입력 기반 생성 도구**. 템플릿은 공공 기준 연동, 면책 고지 |
| 개인정보 | 근로자 동의 절차, 최소 정보만, 링크 만료 |
| 이미 있는 기능 아닌가 | 경쟁 분석 3-2 포지셔닝 맵으로 "이체 연동 + 근로자 대조" 조합이 없음을 보여 준다 |
