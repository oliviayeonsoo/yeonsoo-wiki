# 나무위키 인물 문서 UX/UI 구조 분석

- **대상 문서**: 이예찬(李汭燦) — 리그 오브 레전드 프로게이머 / namu.wiki/w/이예찬
- **분석일**: 2026.08.14
- **분석 방법**: 실제 브라우저로 데스크톱 폭(약 1126px), 모바일 폭(390px, iframe 강제 렌더링)에서 직접 조작. 각주 클릭, 접기/펼치기 토글, CSS 미디어쿼리 추출 등 실인터랙션 테스트.

---

## 1. 전체 구조 개요

"the seed" 위키 엔진 기반. **상단 고정 헤더 → 문서 메타 영역 → 2단(본문+사이드바) 레이아웃 → 하단 푸터**의 전형적 위키형 구조.
미디어위키(위키백과)와의 차이: 프로필 인포박스, 접이식 네브박스(팀 로스터), 우측 실시간 위젯, 고정 플로팅 내비게이션 등 **커뮤니티형 위키 특유의 장식적·인터랙티브 요소**가 다수 추가됨.

### 페이지 컴포넌트 트리 (상→하)

| # | 컴포넌트 | 구성 |
|---|---|---|
| ① | 전역 헤더 | 로고, 주요 내비(최근 변경/최근 토론/특수 기능), 검색창, 랜덤문서, 계정 아이콘 |
| ② | 문서 타이틀 영역 | H1 제목, 편집 횟수 뱃지(원형 숫자), 즐겨찾기/편집요청/토론/역사/더보기 버튼 행, 최근 수정 시각 |
| ③ | 분류(카테고리) 스트립 | 파이프(`|`) 구분 태그 목록 + "더 보기" 인라인 확장 토글 |
| ④ | 안내 핫노트(hatnote) | 동명이인 문서 링크 등 조건부 안내 박스 |
| ⑤ | 접이식 네브박스(템플릿) | 소속팀 로스터, 관련 문서 모음 등 재사용 접기/펼치기 블록 |
| ⑥ | 목차(TOC) + 인포박스 | 데스크톱은 나란히, 모바일은 세로 스택 + 순서 재배치 |
| ⑦ | 본문 섹션 | 번호 매김 헤딩 + 접기 토글 + 섹션별 [편집] + 각주 참조 |
| ⑧ | 각주(footnote) 목록 | 문서 최하단, 번호별 상세 설명 |
| ⑨ | 라이선스 고지 + 네이티브 광고 카드 | |
| ⑩ | 우측 사이드바 (데스크톱 전용) | 실시간 검색어, 최근 변경(실시간 갱신), 디스플레이 배너 광고 |
| ⑪ | 플로팅 액션 클러스터 | 목차 바로가기 / 맨 위로 / 맨 아래로 (뷰포트 고정, 전 구간 노출) |

## 2. 와이어프레임

### 데스크톱 레이아웃 (≥1024px)

```
① 헤더: 로고 · 최근변경 · 최근토론 · 특수기능 ▾ | 검색창 | 계정
   (가로 1행, sticky 아님 — 스크롤 시 사라짐)
② 문서 제목 H1 + 편집뱃지(27) + [★ 편집요청 토론 역사 ⋮]
③ 분류: 태그1 | 태그2 | … [더 보기]
④ ➜ 동명이인 안내 핫노트
⑤-a 접이식 네브박스 — 소속팀 로스터 [펼치기·접기]
⑤-b 접이식 네브박스 — 관련 문서 [펼치기·접기]

┌──────────────────────────────┬──────────────┐
│ ⑥-a 목차(TOC)                │ ⑩ 실시간 검색어 │
│   번호 목록, 하위섹션 들여쓰기 │   순위 자동갱신 │
│   문서링크는 파란색            ├──────────────┤
│ ⑥-b 인포박스(프로필)          │ ⑩ 최근 변경    │
│   사진·표(라벨-값)·서명·SNS행  │  1~2초 간격 교체│
├──────────────────────────────┤              │
│ ⑦ 본문 1. 개요 [편집]         │ 배너 광고      │
│ ⑦ 본문 2. 플레이 스타일 [편집] │ 세로형, sticky │
│    문단 내 각주 [10][11] 산재  │              │
│ ⑦ … 이하 반복 (총 8개 대분류)  │              │
│ ⑧ 각주 목록 [1]~[43]          │              │
│ ⑨ CC 라이선스 + 네이티브광고3열│              │
└──────────────────────────────┴──────────────┘
                                    ⑪ FAB: ≡ ↑ ↓ (우하단 고정)
```

### 모바일 레이아웃 (~390px)

```
① 헤더 1행: 로고 + 아이콘 전용 내비 (텍스트 라벨 숨김)
① 헤더 2행: 검색창 (전체 폭 독립 행)
② 제목 + 메타 아이콘
③ 분류 태그 (줄바꿈)
④ 핫노트
⑤ 네브박스 (전체 폭)
⑥-b 인포박스 (전체 폭)   ★ TOC보다 먼저 — 데스크톱과 순서 반대!
⑥-a 목차(TOC)
⑦ 본문 섹션들
⑧ 각주 / ⑨ 라이선스
⑩ 최근 변경 위젯        ★ 사이드바가 아니라 푸터 하단으로 이동
   앱스토어 배지 + 사이트 정보
```

### 모바일 재배치 규칙 (관찰됨)

- **실시간 검색어 위젯은 좁은 화면에서 완전히 사라짐** — 공간 우선순위에서 제외
- **최근 변경 위젯**: 사이드바 → 본문 최하단(라이선스 아래)으로 이동, 접힌 리스트 + "›" 더보기
- **인포박스**: 데스크톱에선 TOC 옆, 모바일에선 TOC보다 **먼저** 노출 → "얼굴 사진·핵심 프로필부터 보여주기" 의도
- **플로팅 FAB**: 데스크톱·모바일 동일하게 우측 하단 고정 유지

## 3. 반응형 브레이크포인트

페이지 CSS에서 실제 사용 중인 미디어쿼리를 추출. 단순 2단 반응형이 아니라 **세밀한 다단계 체계**.

| Breakpoint (px) | 추정 대상 | 비고 |
|---|---|---|
| 320 / 371.98 / 399.98 / 420 | 소형 스마트폰 | 버튼·텍스트 축약 단계 세분화 |
| 415 / 550 | 대형 스마트폰~패블릿 | 인포박스 폭 조정 추정 |
| 600 | 소형 태블릿 | 일부 컴포넌트 전용 |
| **727.98 / 728** | 태블릿 (모바일↔데스크톱 경계) | **사이드바 표시 여부가 갈리는 핵심 breakpoint** |
| 1023.98 / 1024 | 소형 데스크톱 | 2단 레이아웃 확정 지점 |
| 1199.98 / 1200 / 1400 | 대형 데스크톱 | 본문 최대폭·여백 확장 |
| 1600 + 8rem 이상 | 초광폭 모니터 | 과도한 라인 길이 방지 상한 |
| `prefers-color-scheme: dark` | 다크모드 | OS 설정 연동 |
| `prefers-reduced-motion` | 모션 최소화 | 접근성 대응 |

> ※ `window.resize`로는 실제 렌더 폭이 안 바뀌어(확장 프로그램 환경 제약), 동일 오리진 iframe에 임베드해 390px 뷰포트를 강제 생성하여 실측.

## 4. 디테일 인터랙션 요소

### 4-1. 각주 `[1]` 클릭 동작 (실측)

- 인포박스의 `가족: 부모님, 누나, 형[1]` 에서 `[1]` 클릭 → **페이지가 즉시 문서 최하단 각주 목록으로 점프**(앵커 스크롤).
- 위키백과식 **호버 미리보기 팝업이 아님** — 순수 앵커 링크(`#fn-1`) 기반 이동형 각주.
- 이동 후 해당 각주 텍스트가 리스트 맨 위에 노출.
- **본문 복귀 "↩ back-link" 없음** — 브라우저 뒤로가기 의존. 위키백과의 `^` 리턴 링크보다 불친절.
- 내부 링크(파란 텍스트) 호버 시에도 미리보기 카드 없음 — 클릭 후 페이지 이동만 지원.

### 4-2. 섹션 헤딩의 3중 기능

한 줄에 세 기능이 결합:
1. **`⌄` 접기/펼치기 셰브런** — 클릭 시 해당 섹션 전체 토글 (긴 문서 탐색 편의)
2. **헤딩 텍스트** — TOC에서 점프해오는 앵커 타겟 (`id="s-1"` 형태 추정)
3. **우측 `[편집]` 링크** — 문서 전체가 아닌 해당 섹션만 편집기로 진입

### 4-3. TOC의 자동 링크 컬러링 ★

- 파란색 항목("3. 선수 경력", "5. 밈") = **별도 하위 문서로 분리된 섹션** (예: `이예찬/선수 경력`)
- 검정색 항목("1. 개요", "2. 플레이 스타일") = 현재 문서 내부 앵커
- → **색상만으로 "이 섹션이 전용 상세 문서를 갖는지"를 즉시 구분**하도록 설계됨.

### 4-4. 접이식 네브박스 — 프로그레시브 디스클로저

빨강/검정 배색의 "Nongshim RedForce 2026 시즌 로스터" 박스는 기본 접힘 → `[펼치기·접기]` 클릭 시 감독·코치·포지션별 로스터 표(TOP/JGL/MID… 아이콘 + 국기 + 실명 + 게이머명 뱃지)가 **페이지 이동 없이 인라인 확장**. 여러 선수/팀 문서에서 재사용되는 트랜스클루전 템플릿으로 추정.

### 4-5. 인포박스(프로필 카드) 세부 구성

1. 상단 큰 프로필 사진
2. 소속팀 배너(팀 로고 + 선수명)
3. 실명 / 한자 / 영문명 표기
4. 라벨-값 2열 표: 출생, 국적(국기 아이콘), 학력, 본관, 신체, 가족, 병역, 종교, MBTI, ID, 포지션, 경력 상금(달러+원화 병기), 데뷔일(대회 뱃지 + **"데뷔일로부터 +3928일째" 자동 계산 표시**)
5. **"소속" 행 내부에 또 다른 접이식 미니 박스가 중첩** — 이적 이력 펼쳐보기 (접이식 컴포넌트의 재귀적 사용)
6. 서명 이미지, LPL No., 에이전시
7. 맨 아래 SNS 아이콘 행(X/Instagram/Weibo/知乎/치지직) — 외부 링크 아이콘 버튼 그룹

### 4-6. 실시간 갱신 위젯 (데스크톱 사이드바)

우측 "실시간 검색어" / "최근 변경"은 몇 초 간격 재캡처마다 항목·순위가 계속 바뀜 — 폴링 또는 웹소켓 기반 실시간 갱신. "11초 전", "1분 전" 상대시간 타임스탬프도 자동 업데이트. **정적인 본문과 대비되는 "살아있는" 사이드바 연출.**

### 4-7. 네이티브 광고 카드

각주 하단·라이선스 고지 바로 위에 본문과 유사한 카드 형태(제목+도메인+설명)의 네이티브 광고 3개가 검색 결과 스니펫처럼 삽입. 우측 배너 광고와는 다른 포맷(문맥 광고 네트워크 연동으로 보임).

## 5. UX 관점 요약 평가

### ✓ 잘 설계된 점
- 인포박스·네브박스가 **템플릿화**되어 수만 개 인물 문서에 일관된 정보 스캐닝 패턴 제공
- **섹션 접기 + 자체 TOC + 플로팅 FAB** 조합으로 25,000px 넘는 초장문에서도 탐색성 확보
- 모바일에서 **인포박스를 TOC보다 앞으로 재배치** — 첫 스크롤에 "누구인지" 즉시 파악
- 9단계 이상 세밀한 반응형 브레이크포인트

### △ 아쉬운 점
- 각주에 본문 복귀 링크 없음 → 긴 각주 읽고 나면 수동 스크롤/뒤로가기 필요
- 내부 링크 호버 미리보기 부재 → 관련 인물/팀 확인마다 페이지 이동
- 모바일에서 "실시간 검색어" 완전 삭제 → feature parity 결여
- 네이티브 광고가 본문과 시각적으로 유사해 광고/본문 구분 모호
